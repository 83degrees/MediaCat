# DDR-03-002 — Adopt the MediaCat Runtime Namespace Through Parallel Migration

## Status

Proposed

## Decision

MediaCat adopts `mediacat` as its Home Assistant integration domain, service
namespace, Media Source domain, and configuration-directory name. The
user-facing integration and Media Source name is `MediaCat`.

The logical catalogue identifier remains `curated_media`. Runtime namespace and
catalogue identity are separate concepts and are not renamed together.

The namespace change is introduced through parallel deployment. The new
`mediacat` integration and `/config/mediacat/catalogue.yaml` coexist with the
legacy `curated_media` integration and catalogue path while each active
consumer migrates independently. The legacy namespace may be removed only
after active-reference scans and runtime validation prove that no active
consumer still depends on it.

## Context

MediaCat's product identity and its deployed implementation identity diverged:
the product was named MediaCat while the Home Assistant integration, service
namespace, Media Source domain, and configuration directory were named
`curated_media`. The normalized lookup is consumed across the MediaCat, ASTV,
and AdvMedia product boundaries, so changing its service namespace is an
externally visible architectural and contract change.

The catalogue root also declares `catalogue_id: curated_media`. That value
identifies the logical catalogue selected by lookup requests; it is not the
Home Assistant integration domain. Renaming it would change catalogue-scoped
identity and is outside ASTV-221.

A direct replacement would make every consumer and the provider change at the
same instant. The retained legacy domain provides a bounded rollback route
while the producer and consumers move through separately reviewed and validated
changes.

## Alternatives considered

1. Replace `curated_media` with `mediacat` in one coordinated cutover.
2. Keep `curated_media` permanently as the runtime namespace while changing
   only the user-facing name.
3. Introduce `mediacat` in parallel, migrate consumers independently, then
   retire `curated_media` after readiness proof. This is the selected option.
4. Rename both the runtime namespace and logical catalogue identifier in the
   same change.

## Rationale

The selected option aligns the externally visible implementation with the
product identity without forcing a simultaneous cross-product cutover. Distinct
Home Assistant domains provide independent service registration, Media Source
identity, and `hass.data` storage, allowing functional parity and rollback to
be proved before the legacy path is removed.

Preserving `catalogue_id: curated_media` limits the compatibility change to the
runtime namespace. Consumers can change the action domain while keeping the
same request identity and returned-record contents.

## Consequences / trade-offs

- MediaCat temporarily maintains two functionally equivalent Home Assistant
  integrations and two catalogue-file locations.
- The two domains must not share mutable state, caches, or service
  registrations; parity and coexistence require explicit validation.
- ASTV, AdvMedia, and any additional active consumer migrate in independent
  governed work while the legacy domain remains available for rollback.
- Documentation and contracts must distinguish the approved `mediacat` target,
  the temporary legacy compatibility surface, historical evidence, and the
  unchanged `curated_media` catalogue identity.
- Legacy removal is a gated final phase, not an automatic consequence of adding
  the new domain.
- The returned-record schema and `returned_record_version: 1` remain unchanged.
