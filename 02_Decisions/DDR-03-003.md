# DDR-03-003 — Public artwork hosting for MediaCat

## Status

Proposed

## Decision

MediaCat public artwork used by consumers that require Internet-reachable image
URLs will be hosted in Cloudflare R2 Standard storage.

The R2 bucket is an external delivery surface for MediaCat-owned artwork. It
does not become a MediaCat runtime dependency for catalogue loading or item
lookup: the catalogue stores an absolute HTTPS URL in `artwork.external`, and
consumers fetch that URL independently.

Object keys use stable media-type paths based on catalogue identity, for example:

- `radio/classic-fm.png`
- `tv/bbc-iplayer.png`

Production URLs should be served through a Cloudflare R2 custom domain. The
Cloudflare-managed `r2.dev` public endpoint may be used only for setup and
verification because Cloudflare documents it as a non-production endpoint.

Home Assistant instances, including `ha-shorefoot`, are not exposed to the
public Internet solely to serve MediaCat artwork.

## Context

Google Cast consumers need artwork to be retrievable over unauthenticated public
HTTPS. Home Assistant `/local/...` paths, Tailscale-only addresses, and
care-home LAN addresses are not suitable public delivery endpoints.

Schema v3 already supports this requirement through optional
`artwork.external`, defined as an absolute HTTP(S) URL. The existing consumer
behaviour prefers the external artwork value for Google Cast, so no catalogue
schema or normalized lookup-contract change is required.

The hosting choice is durable because catalogue metadata will embed the chosen
public delivery URLs and future artwork maintenance will depend on the selected
hosting model.

## Alternatives considered

### GitHub Pages

GitHub Pages provides HTTPS static hosting and would be sufficient for the
expected low traffic and small asset volume. However, the MediaCat repository is
private and Pages is currently disabled. Publishing Pages from a private
repository depends on GitHub plan capability, making that route conditional on
account configuration rather than purely on MediaCat architecture.

Pages also couples asset delivery to a static-site publishing mechanism rather
than purpose-built object storage.

### Cloudflare R2

R2 is purpose-built object storage with public HTTPS delivery, a free monthly
allowance substantially above MediaCat's expected artwork footprint, and no
Internet egress charge. Public production delivery can use a custom domain
without exposing Home Assistant.

Its main additional operational requirement is a Cloudflare account/R2
subscription and initial bucket/domain configuration.

## Rationale

R2 separates public asset delivery from Home Assistant and from the private
MediaCat source repository while preserving stable object paths.

It matches the requirement more directly than a static-site publishing
mechanism, provides a low/no-cost operating envelope for the expected workload,
and leaves MediaCat's catalogue schema unchanged.

The custom-domain production path also allows the public hostname to remain
stable if underlying storage implementation details later change.

## Consequences / trade-offs

- MediaCat gains an external hosting dependency for public artwork delivery.
- Catalogue authors continue to use `artwork.local` where useful for Home
  Assistant-local presentation and use `artwork.external` for public consumers.
- Artwork object names and paths become durable references and should not be
  casually renamed.
- Replacing artwork at an existing path preserves catalogue URLs; cache behaviour
  may delay visual replacement depending on hosting configuration.
- Initial Cloudflare account, bucket, public-access, and custom-domain setup is
  operational work outside the MediaCat repository.
- The `r2.dev` endpoint is suitable for setup/testing only, not the intended
  production URL surface.
- If R2 later becomes unsuitable, migration should preserve the public hostname
  and object-path structure where practical.
